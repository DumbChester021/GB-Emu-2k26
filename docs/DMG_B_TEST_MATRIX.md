# DMG-CPU B Test Matrix

> **Target:** Nintendo DMG-01 with the DMG-CPU B SoC
> **Automated command:** `bash run_dmg_b_regression.sh`
> **Last audited:** 2026-08-11

This project gates only behavior that applies to DMG-CPU B. A test being useful
for future CGB work does not make it part of the current DMG regression score.

## Mooneye Selection

Mooneye's upstream naming defines `G` as DMG+MGB, `S` as SGB+SGB2, and `C` as
CGB+AGB+AGS. Untagged tests are universal. The DMG-B gate therefore includes:

- untagged acceptance tests;
- `-G` and `-GS` tests because both groups contain DMG;
- `-dmgABC` and `-dmgABCmgb` tests because revision B is included;
- model-neutral `emulator-only/mbc1`, `mbc2`, and `mbc5` tests. "Emulator-only"
  means difficult to verify on a console, not incompatible with DMG-B.

The bundled Mooneye release contains **66 compatible acceptance ROMs** and
**28 compatible emulator-only MBC ROMs**, for a total of **94**.

These nine acceptance ROMs are intentionally excluded:

| Reason | ROMs |
|--------|------|
| DMG-0 only | `boot_div-dmg0`, `boot_hwio-dmg0`, `boot_regs-dmg0` |
| MGB only | `boot_regs-mgb` |
| SGB/SGB2 only | `boot_div-S`, `boot_div2-S`, `boot_hwio-S`, `boot_regs-sgb`, `boot_regs-sgb2` |

`misc` CGB/AGB tests, `manual-only`, and `madness` are not included in the
automated DMG-B total. The selection rules come from the
[Mooneye Test Suite README](https://github.com/Gekkio/mooneye-test-suite).

One universal `manual-only` ROM, `sprite_priority.gb`, ships with an exact
upstream reference PNG. The regression runner promotes it to a strict
pixel-comparison gate, but keeps it outside Mooneye's 94-ROM result-protocol
score.

## Other Automated Suites

| Suite | DMG-B policy | Regression rule |
|-------|--------------|-----------------|
| Blargg CPU/instruction/memory timing | Include DMG-compatible ROMs | Serial or memory result must pass |
| Blargg `dmg_sound-2` | Include all 12 singles | All must pass |
| Blargg `oam_bug` and `oam_bug-2` | Include both combined ROMs | Both must report 8/8 |
| Blargg `cgb_sound` | Exclude | CGB-only behavior |
| Mealybug Tearoom | Run all 24 DMG ROMs | Existing exact-image passes may not regress |
| DMG-ACID2 | Include | Must match the upstream DMG reference pixel-for-pixel |
| CGB-ACID2 | Exclude | Becomes relevant when CGB mode exists |

The current committed baseline is Mooneye **90/94** (PPU 8/12), Mealybug
**5/24**, both Blargg OAM suites **8/8**, `dmg_sound-2` **12/12**, and exact
matches for Mooneye sprite priority and DMG-ACID2. The four known Mooneye gaps
are `intr_1_2_timing-GS`, `intr_2_mode0_timing_sprites`, `lcdon_timing-GS`, and
`lcdon_write_timing-GS`.

Mealybug has only two explicit `DMG-CPU B` expected images in this checkout.
The runner uses those first and falls back to the suite's `DMG-blob` image for
the other 22 tests. It never compares the DMG core against CPU CGB C/D images.
The reference source is printed beside every result. A missing framebuffer,
invalid comparison, or manifest other than 24 ROMs is a hard runner error, not
an ordinary accuracy mismatch.

DMG-ACID2 is compared against the upstream
`dmg-acid2-master/img/reference-dmg.png`, not a screenshot generated by this
emulator.

## Deliberately Non-Gating Work

- Other Mooneye `manual-only`/`madness` cases are excluded: none are applicable
  automatable DMG-B checks in the bundled release (`madness` is MGB-specific).
- Blargg `halt_bug` is still executed, but it is visual-only and has no
  machine-readable completion protocol. Mooneye's four DMG-compatible HALT
  tests are the strict automated gate.
- MBC3 RTC behavior is valid DMG functionality, but `rtc3test` is not bundled
  and the RTC is not implemented. It is an explicit future target, not counted
  as a current pass.
- SameSuite should be added when its DMG-B expected outputs and an automated
  result adapter are vendored. CGB-specific SameSuite cases must stay outside
  the DMG score.

## Accuracy Policy

The regression script protects known-good behavior; it is not permission to
add per-ROM offsets or expected-output hacks. Timing changes must follow a
hardware state transition or bus phase, and a deliberate regression is accepted
only when it replaces an inaccurate abstraction with a more faithful model and
is documented with before/after measurements.
